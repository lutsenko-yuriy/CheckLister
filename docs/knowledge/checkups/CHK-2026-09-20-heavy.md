## Findings

### Accessibility

- **Finding:** `colors.textMuted` (`#5C7189`) against `colors.background`/`colors.surface` (`#EAF2FB`) measured 4.45:1 — just under the WCAG AA 4.5:1 minimum for normal text. `textMuted` is used app-wide as the color for secondary/body text (item counts, empty states, run progress, history subtitles), not just icons or large text, so the shortfall applied broadly.
- **Debt quadrant:** prudent-inadvertent (palette was tuned for look, not measured against WCAG at the time — CheL-14).
- **Disposition:** fixed inline (same commit as this write-up) — `textMuted` changed to `#55698A` (4.93:1 against the background), verified with a standalone WCAG relative-luminance calculation; no hardcoded references to the old hex existed outside `colors.ts`, and the full Jest suite (162 tests) plus lint stayed green.
- **Graduation candidate:** yes — a scripted contrast check (compute all `colors.ts` pairs actually used as `color`-on-background in `src/`, fail under 4.5:1 for text-sized usage) could run in CI once the palette stabilizes further; not proposed as a CI check yet since it would need to distinguish text from icon/UI-component usages (3:1 threshold) to avoid false positives.

- **Finding:** `colors.primary` (`#2F6FEE`) used as `RunScreen.tsx`'s "Back" button text color measured 4.02:1 against the background — under the 4.5:1 AA minimum for 16px text. This is `colors.primary`'s only text-color usage in the app (elsewhere it's a button background or icon fill, where the 3:1 non-text-contrast threshold applies and is met). Darkening `colors.primary` itself would change the app's brand/button color everywhere it's used, which is a design call beyond this checkup's scope.
- **Debt quadrant:** prudent-inadvertent.
- **Disposition:** deferred — see ledger, deadline `2026-10-31`.
- **Graduation candidate:** no.

- **Finding:** `IconButton` (`src/shared/ui/IconButton.tsx`) renders a 22px icon with `hitSlop={8}` and no explicit minimum width/height or padding on the `Pressable`. Effective touch-detectable area is roughly 38×38pt, below the commonly cited 44×44pt (Apple HIG) / 48×48dp (Material) minimum tap-target guidance. Every icon-only action across the app (Add, Rename, Delete, Save, Cancel, Edit, Run history, Back) inherits this.
- **Debt quadrant:** prudent-inadvertent.
- **Disposition:** deferred — see ledger, deadline `2026-11-15` (larger surface: touches a shared component used on every screen, warrants its own scenario/visual check rather than a blind size bump).
- **Graduation candidate:** yes — once a minimum size is settled, a lint/unit check asserting `IconButton`'s rendered hit area meets the threshold could graduate into the test suite.

- **Finding:** `scripts/notes/index.py --check` failed: `CheL-3.md`, `CheL-4.md`, `CheL-5.md`, `CheL-14.md`, `CheL-20.md`, and `CheL-36.md` were missing the required `bookmarks:` frontmatter key entirely (this project's first-ever checkup run, so the corpus had never been swept). `BOOKMARKS.md`'s vocabulary table was also still empty. Reading all six notes plus a re-check of `CheL-26.md` (tagged `bookmarks: []` but, on rereading, containing taggable recurring content) surfaced three real recurring themes across the corpus: async/native lifecycle races found only during implementation (CheL-36), bugs/quirks only discoverable via real-device or simulator testing (CheL-4, CheL-26), Maestro scenario fixtures that can't be fully cleaned up through the product UI (CheL-5, CheL-26), and OpenAI/Codex model-effort-calibration friction repeated near-verbatim across two debriefs (CheL-26, CheL-36).
- **Debt quadrant:** prudent-deliberate (the bookmark system was intentionally seeded empty at project start, with this exact quarterly sweep as the known payoff point — see `BOOKMARKS.md`'s own "starts empty on a fresh project" note).
- **Disposition:** fixed inline (same commit as this write-up) — added four bookmarks to `BOOKMARKS.md` (`async-lifecycle-races`, `real-device-only-bugs`, `scenario-fixture-isolation`, `agent-model-calibration`), tagged the six untagged notes plus re-tagged `CheL-26.md`, left `1.md`/`2.md`/`CheL-15.md` as `bookmarks: []` (their content is one-off process feedback already folded into `docs/workflows/FEATURE.md`, not a recurring corpus theme), and regenerated `INDEX.md`. `scripts/notes/index.py --check` now passes.
- **Graduation candidate:** no — this dimension is already mechanically checked by `scripts/notes/index.py --check`; the judgment call (which recurring pattern deserves a new bookmark) is inherently human/agent review, not automatable.
