**Organize tickets as soon as features are identified, not on a separate ask**

While filling in `docs/PRODUCT_SPEC.md`, all 5 v1 features were fully
clarified through dialog in the same session. The user then had to
separately ask "organize features into tickets" as a follow-up step. Once a
feature is unambiguous and coherent (the same bar the `brief` skill's step 3
already uses to decide whether to proceed to ticket creation), there's no
reason to wait for an explicit "make tickets" request — go ahead and create
the tickets right away as part of identifying the features, rather than
treating spec-writing and ticket-organizing as two separately-triggered
steps.
