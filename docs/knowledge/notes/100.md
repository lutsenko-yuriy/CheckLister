# CheL-100: Run Android Maestro scenarios in CI on PR open

## Notes

- 2026-09-30: CI run #1 lost the emulator mid-suite. After the first flow passed (~2 min into the suite), adb reported `emulator-5554` as `device offline`. The next flow's very first call (Maestro clearing logcat) already failed, and the other 5 flows errored in under 150 ms each (`DeviceServerDiedException ... UNAVAILABLE`). The emulator process itself stayed up (`emu kill` succeeded afterwards). It didn't recur in runs #2–#7. Rather than guess a fix from one sample, a post-run `logcat.txt` dump (only after Maestro exits, per `docs/CONSTRAINTS.md`) and a host `dmesg` step were added, so a recurrence carries its own evidence.
- 2026-09-30: `paths:` on a `pull_request` trigger is evaluated against the **whole PR diff**, not the latest push. A docs-only commit on a PR that already touches app paths still starts the workflow, and cancels the in-flight run through `cancel-in-progress`. I wrongly told the user the opposite mid-session.
- 2026-09-30: `dorny/test-reporter` with `fail-on-error: false` concludes the check as **success** even when the report contains failures. Run #5 (5 passed, 1 failed) showed a green "Android scenario flows" check. Fixed by leaving it at the default; a contract test pins that.
- 2026-09-30: Run #5's failing flow had item text truncated at the space ("Scenario second" → "Scenario"), on a fresh CI emulator. `110.md` had recorded the same symptom as a degraded-emulator false lead; the fresh-emulator sighting contradicts that. Filed as CheL-116.
- 2026-09-30: Measured timing: ~10 min cold `assembleRelease` (x86_64), ~1.5 min emulator boot, 7–10.5 min suite, 19–24 min per green run. The Gradle cache is never written from PR runs (`setup-gradle` writes only from the default branch), which the push-to-`main` trigger now fixes. Speeding up the workflow is CheL-115.
