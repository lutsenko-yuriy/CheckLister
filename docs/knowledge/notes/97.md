# 97: Isolate Android Maestro scenarios from persistent test data

## Notes

### 2026-09-27

- 2026-09-27: Empirical spike on `Pixel_5_API36` (booted, existing app data preserved) corrected the plan's mechanism: `adb shell run-as com.checklister ...` fails with `run-as: package not debuggable` against the Release APK the scenario suite actually installs (Release builds are never debuggable — expected, matches CheL-34's iOS use of Release builds too). `adb root` works reliably instead, because `Pixel_5_API36`'s system image is tagged `google_apis` (`tag.id=google_apis` in its `config.ini`) — a userdebug image that permits root — not a `google_play` image, which would refuse it. Confirmed full round-trip directly as root, no `run-as` wrapping needed: `adb exec-out tar -c -C /data/data/com.checklister --exclude ./cache --exclude ./code_cache --exclude ./lib .` captures cleanly (5.2MB, correct `shared_prefs`/`files`/`databases` contents); `adb push` to `/data/local/tmp/` + `cat <tar> | tar -x -C /data/data/com.checklister` restores cleanly, with ownership (`u0_a213:u0_a213`) preserved automatically by `tar` under root — no `chown` step needed. A marker file written post-capture was correctly removed by restore's allowlisted `rm -rf ./files ./databases ./shared_prefs ./no_backup` before extraction. Post-restore, `adb shell am start -n com.checklister/.MainActivity` launched cleanly with the restored data visible in the UI — no crash, no `SELinux... denied` in logcat. Also confirmed empirically: no `./lib` entry exists under `/data/data/com.checklister` on this API level (native libs live under `/data/app/.../lib` instead, not copied into app-private storage) — the exclude pattern is harmless but currently a no-op.
- 2026-09-27: **Plan correction:** drop the `run-as` ladder rung entirely as the primary mechanism (it will essentially never succeed against this project's Release-build scenario target) — use `adb root` as the sole mechanism, fail loudly with a `docs/SCENARIOS.md` pointer (Google APIs image requirement) if root is refused. `docs/SCENARIOS.md`'s Android setup section needs a new line calling out that the chosen system image must be tagged **Google APIs**, not **Google Play** — the latter blocks `adb root` and would break this mechanism entirely. This wasn't previously documented as a setup requirement because nothing before this ticket needed root.
