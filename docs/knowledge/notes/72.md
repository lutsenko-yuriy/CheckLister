# 72: Faster iOS PR-validation build (Debug config, spec-repo cache, path filtering)

## Notes

## Debrief summary

### 2026-09-23

**What went well**
- Explored multiple strategies (Debug config, CocoaPods spec-repo cache, path-based job skip, Xcode DerivedData cache), tested each empirically against real CI runs, and kept the ones that measured as actual wins rather than assuming any of them would work.

**What was hard or surprising**
- Nothing — the shape of the investigation matched expectations going in.

**What to change**
- Nothing identified. The remaining ~10-13 minutes is genuine `xcodebuild` from-scratch compile time for a PR that touches native code; DerivedData caching (the strategy expected to help most) turned out to be a dead end because a fresh `git checkout` resets file mtimes, so Xcode's incremental build never recognizes the restored cache as reusable — confirmed empirically (2026-09-23), not assumed. Further reduction would need a bigger investment (e.g. ccache/sccache for clang, a warm self-hosted runner) than this ticket's scope, and CI wait time itself isn't something process changes can shorten.
